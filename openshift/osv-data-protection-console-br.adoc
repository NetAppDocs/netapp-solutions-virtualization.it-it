= Esegui il backup e il ripristino delle VM utilizzando il servizio Backup and Recovery di NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Esegui il backup e il ripristino delle VM in Red Hat OpenShift Virtualization usando NetApp Console. Questa procedura copre la creazione e la gestione delle operazioni di backup e ripristino tramite Backup and Recovery Service tramite NetApp Console, utilizzando un container Azure Blob Storage come destinazione del backup.

NetApp Console offre una gestione centralizzata dei servizi di storage e dati in ambienti on-premises e cloud. Offre controllo unificato, semplicità operativa e gestione sicura. Sono disponibili diversi servizi dati e funzionalità di gestione accessibili dall'interfaccia utente su link:https://console.netapp.com["console.netapp.com"^]. Per dettagli completi su NetApp Console, vedi link:https://docs.netapp.com/us-en/console-family/["Documentazione di NetApp Console"].

Questa sezione si concentra sul servizio dati NetApp Backup and Recovery per i carichi di lavoro Kubernetes, in particolare sulle macchine virtuali OpenShift. Il servizio NetApp Backup and Recovery ti permette di individuare, gestire, creare e associare criteri di protezione alle tue applicazioni e VM Kubernetes tramite un'unica interfaccia. Per una guida completa, vedi link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["NetApp Backup and Recovery documentazione"].

== Flusso di lavoro di backup e ripristino

. *Assicurati di avere un Console Agent*
+
Assicurati di aver distribuito un agente console nell'ambiente in cui è in esecuzione il tuo cluster OpenShift. Per dettagli sull'installazione di un agente console, consulta la link:https://docs.netapp.com/us-en/console-setup-admin/concept-agent-install-options.html#agent-console-deploy["NetApp Console documentazione di configurazione"].

+
.Mostra esempio
[%collapsible]
====
Nella NetApp Console, fai clic su Deploy Agent come mostrato nello screenshot e distribuisci l'agente nell'ambiente in cui è in esecuzione il cluster OpenShift.

In questo esempio, abbiamo scelto l'installazione locale. Copia l'URL del programma di installazione dell'agente, usa il comando curl per scaricare il programma di installazione dell'agente sulla macchina Ubuntu in esecuzione su vSphere, e avvia il programma di installazione per distribuire l'agente della Console.

Registralo utilizzando l'indirizzo IP dell'agente nell'URL. Consulta link:https://docs.netapp.com/us-en/console-setup-admin/task-install-agent-on-prem-ova.html["la documentazione"] per istruzioni dettagliate. Dopo che l'agente è stato registrato, puoi vederlo in NetApp Console come mostrato nello screenshot qui sotto.

. *Configura un container Azure Blob Storage come destinazione di backup per uno scenario di backup e ripristino delle VM OpenShift.*
+
In questo esempio, utilizziamo Azure Blob Storage come destinazione di backup. Puoi anche utilizzare AWS S3, Google Cloud Storage, StorageGRID o ONTAP object storage come destinazioni di backup.

+
Per ulteriori dettagli, consulta link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-start-setup.html#prepare-the-backup-destination["Documentazione di NetApp Console"].

+
Per individuare il container Azure Blob Storage come destinazione di backup nella NetApp Console, ti serviranno le seguenti informazioni dal portale di Azure.

+
[listing]
----
Application (Client) ID:
Client Secret:
Directory (tenant) ID:
----
+
Per ottenere questi valori, procedi come segue nel portale di Azure.

+
.. Crea un container Blob Storage.
.. Crea un'applicazione aziendale e assegna a tale applicazione l'accesso necessario al container Blob Storage. Recupera l'Application ID, il Directory ID e il Client Secret di questa applicazione per utilizzarli nella NetApp Console per individuare il container Azure Blob Storage come destinazione di backup.
+

Avrai anche bisogno di una policy di protezione da associare all'applicazione. Puoi creare una nuova policy di protezione o usarne una esistente. In questo esempio, viene creata una nuova policy di protezione con l'applicazione e ad essa associata. I backup vengono creati per l'applicazione in base alla policy di protezione associata. Il numero di backup conservati si basa sulla policy di conservazione definita nella policy di protezione.

Se la tua applicazione/VM ha più di un disco e il backup non riesce con l'errore mostrato di seguito, modifica le  `volumegroupsnapshots` e  `volumegroupsnapshotcontents` regole API in modo che includano i verbi mostrati.

.<strong>Mostra correzione</strong>
[%collapsible]
=====
image:osv-data-protection-console-043.png["Errore durante la protezione di macchine virtuali con più di un disco ciascuna"]

[source, yaml]
----
- apiGroups:
  - groupsnapshot.storage.k8s.io
  resources:
  - volumegroupsnapshots
  verbs:
  - get
  - list
  - watch
  - create
  - delete
  - update
  - patch
- apiGroups:
  - groupsnapshot.storage.k8s.io
  resources:
  - volumegroupsnapshotcontents
  - volumegroupsnapshotcontents/status
  verbs:
  - get
  - list
  - watch
  - create
  - delete
  - update
  - patch
- apiGroups:
  - groupsnapshot.storage.k8s.io
  resources:
  - volumegroupsnapshotclasses
  verbs:
  - get
  - list
  - watch

----
