= Configurazione del cluster di origine per Red Hat OpenShift Virtualization Disaster Recovery
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Questa sezione fornisce informazioni sulla configurazione del cluster di origine per il disaster recovery dei carichi di lavoro di OpenShift Virtualization usando NetApp Trident Protect e AppMirror. Questo include la creazione di un AppVault usando ONTAP S3, la creazione di un'applicazione Trident Protect per la VM di origine e la creazione di snapshot on-demand e pianificati della VM usando Trident Protect. Questi passaggi sono essenziali per assicurarti che il cluster di origine sia configurato correttamente per replicare i dati verso il cluster di destinazione per il disaster recovery e permettere il ripristino delle VM in caso di disastro.



[[setup-disaster-recovery-source-cluster-for-openshift-virtualization]]
== Configura il cluster di origine per il disaster recovery per OpenShift Virtualization

Tutti i passaggi seguenti vengono eseguiti sul cluster di origine, cioè il cluster in cui la VM protetta è attualmente in esecuzione.



[[create-appvault-using-ontap-s3]]
== Crea AppVault utilizzando ONTAP S3

Questa sezione mostra come configurare un oggetto AppVault in Trident Protect utilizzando lo storage a oggetti ONTAP S3. L'oggetto AppVault creato in questo passaggio verrà utilizzato per archiviare i dati replicati dal cluster di origine, e tali dati verranno utilizzati per il ripristino nel cluster di destinazione per il disaster recovery.

Utilizza i comandi oc e i file yaml mostrati di seguito per creare un secret e la risorsa personalizzata AppVault per ONTAP s3. Assicurati di crearli nel namespace trident-protect.

.Mostra esempio
[%collapsible]
====
[source, yaml]
----
apiVersion: v1
# You can provide the keys either as stringData or base 64 encoded data
stringData:
  accessKeyID: "<access key id as obtained from ONTAP>"
  secretAccessKey: "<secret access key as obtained from ONTAP>"
#data:
  #accessKeyID: <base 64 encoded value of access key>
  #secretAccessKey: <base 64 encoded value of secret access key>
kind: Secret
metadata:
  name: appvault-secret
  namespace: trident-protect
type: Opaque

----
[source, yaml]
----
apiVersion: protect.trident.netapp.io/v1
kind: AppVault
metadata:
  name: ontap-s3-appvault
  namespace: trident-protect
spec:
  providerConfig:
    s3:
      bucketName: oc-dr
      endpoint: <data lif to use to access S3>
      secure: "false" # Setting this to "false" will disable TLS, which is not recommended for production environments.
      skipCertValidation: "true" # When TLS is enabled, setting skipCertValidation to "true" will skip TLS certificate validation, which is not recommended for production environments.
  providerCredentials:
    accessKeyID:
      valueFromSecret:
        key: accessKeyID
        name: appvault-secret
    secretAccessKey:
      valueFromSecret:
        key: secretAccessKey
        name: appvault-secret
  providerType: OntapS3
----
Assicurarsi che il vault S3 di ONTAP sia stato creato e si trovi nello stato Disponibile

[source, cli]
----
oc create -f app-vault-secret.yaml -n trident-protect
oc create -f app-vault.yaml -n trident-protect
----

[[create-a-trident-protect-app-for-the-source-vm]]
== Crea un'app Trident Protect per la macchina virtuale di origine

Crea una risorsa personalizzata di tipo Application nel namespace in cui si trova la VM di origine.

.Mostra esempio
[%collapsible]
====
[source, yaml]
----
# cat app.yaml
apiVersion: protect.trident.netapp.io/v1
kind: Application
metadata:
  creationTimestamp: null
  name: test-source-app
  namespace: test-dr-ns
spec:
  includedNamespaces:
  - namespace: test-dr-ns
----
[source, cli]
----
tridentctl-protect create app <source-vm> -n <source-ns> --namespaces <source-ns>
----
image:osv-disaster-recovery-004.png["Applicazione OCP-v nello spazio dei nomi source-ns"]

Di seguito puoi vedere la VM e il relativo PVC nel namespace incluso nella risorsa personalizzata App.

[[create-a-snapshot-of-the-vm-using-trident-protect]]
== Crea una Snapshot della VM utilizzando Trident Protect

Puoi creare uno snapshot on-demand della VM utilizzando la CLI o l'API di Trident Protect. Questo snapshot verrà archiviato nell'AppVault creata nel passaggio precedente e potrà essere utilizzato per il ripristino nel cluster di destinazione per il disaster recovery.

.Mostra esempio
[%collapsible]
====
[source, yaml]
----
# snapshot.yaml
apiVersion: protect.trident.netapp.io/v1
kind: Snapshot
metadata:
  name: test-source-dr-init-snapshot
  namespace: test-dr-ns
spec:
  applicationRef: test-source-app
  appVaultRef: ontap-s3-appvault
  reclaimPolicy: Delete

----
image:osv-disaster-recovery-006.png["Snapshot on-demand di OCP-v della VM creata tramite Trident Protect CLI"]

====


[[create-a-scheduled-snapshot-of-the-vm-using-trident-protect]]
== Crea uno snapshot pianificato della macchina virtuale utilizzando Trident Protect

Puoi anche creare uno snapshot pianificato creando una risorsa personalizzata Schedule nello stesso namespace della risorsa personalizzata Application. La pianificazione creerà automaticamente snapshot della VM secondo la pianificazione specificata e li memorizzerà in AppVault.

.Mostra esempio
[%collapsible]
====
[source, yaml]
----
apiVersion: protect.trident.netapp.io/v1
kind: Schedule
metadata:
  name: appmirror-sched1
spec:
  appVaultRef: ontap-s3-appvault
  applicationRef: test-source-app
  backupRetention: "0"
  enabled: true
  granularity: Custom
  recurrenceRule: |-
    DTSTART:20240901T000200Z
    RRULE:FREQ=MINUTELY;INTERVAL=5
  snapshotRetention: "2"
----
