= Configura un cluster stretch per un dominio workload VCF usando MetroCluster
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
In questo caso d'uso, descriviamo la procedura per configurare un cluster stretch per il dominio di carico di lavoro VMware Cloud Foundation (VCF) utilizzando ONTAP MetroCluster con FC, iSCSI, NVMe-oF, NFSv3 o NFSv4.1 come datastore primario. VCF offre flessibilità nelle opzioni di implementazione in base alle tue esigenze. Lo strumento VCF Ops viene utilizzato per implementare un nuovo dominio di carico di lavoro VCF o per importare un ambiente vSphere esistente in un dominio di carico di lavoro VCF. In questo documento ci concentreremo sulla parte MetroCluster e rimanderemo ad altra documentazione in base alle fasi di implementazione.

image:vmw-vcf-vmsc-viwld-mcc-001.png["Dominio workload VCF con vMSC, width=500"]



[[introduction]]
== Introduzione

In questa soluzione ti mostreremo come implementare uno Stretched VCF Workload Domain con ONTAP MetroCluster come Principal Datastore. MetroCluster permette di implementare una soluzione ad alta disponibilità per tutti i workload in esecuzione sul cluster ONTAP. Se hai bisogno di implementare una soluzione ad alta disponibilità specifica per i workload, valuta l’uso di SnapMirror active sync (SAN e NAS). SnapMirror active sync (SAN) funziona a livello di consistency group, mentre SnapMirror active sync (NAS) funziona a livello di SVM. Per maggiori informazioni, consulta link:vmw-vcf-vmsc-viwld-smas.html["Configura un cluster stretch per un dominio workload VCF usando SnapMirror Active Sync (SAN e NAS)"].



[[prerequisites]]
== Prerequisiti

Questo scenario richiede i seguenti componenti e configurazioni:

* Configurazione ONTAP MetroCluster supportata
* Macchina virtuale di storage (SVM) configurata con il protocollo storage preferito.
* È stata creata un'interfaccia logica (LIF) per gestire il traffico storage ed è associata all'SVM.

[[deployment-steps-for-greenfield-vcf-workload-domain-with-metrocluster]]
== Passaggi di distribuzione per il workload domain VCF Greenfield con MetroCluster

Per le implementazioni Greenfield (nuove implementazioni senza componenti VCF preesistenti), lo strumento VCF Ops viene utilizzato per distribuire il dominio del carico di lavoro. In questo scenario sono supportati VMFS su FC e NFSv3.

Nel caso di VMFS su FC, consulta link:vmw-vcf-viwld-principal-fc.html["Dominio workload VCF con datastore VMFS basato su FC su ONTAP come storage principale"] per maggiori informazioni. Per NFSv3, consulta link:vmw-vcf-viwld-principal-nfs.html["Dominio workload VCF con datastore NFSv3 su ONTAP come storage principale"] per maggiori informazioni.



[[deployment-steps-for-brownfield-vcf-workload-domain-with-metrocluster]]
== Passaggi di distribuzione per il workload domain VCF Brownfield con MetroCluster

Un'implementazione brownfield è uno scenario in cui hai un ambiente vSphere esistente e vuoi importarlo come dominio di workload VCF.

Per iSCSI, NVMe-oF e NFSv4.1, devi configurarlo con vCenter (preferibilmente con ONTAP tools) e poi usare lo strumento VCF Ops per importarlo come workload domain. Per ulteriori informazioni, consulta link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/building-your-private-cloud-infrastructure/working-with-workload-domains/import-an-existing-vcenter-to-create-a-workload-domain.html["Importa un vCenter esistente per creare un dominio di carico di lavoro"].
