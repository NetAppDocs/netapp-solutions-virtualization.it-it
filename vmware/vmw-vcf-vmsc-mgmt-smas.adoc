= Configura un cluster stretch per un dominio di gestione VCF usando SnapMirror Active Sync (SAN e NAS)
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
In questo caso d'uso descriviamo la procedura per utilizzare gli ONTAP tools for VMware vSphere per configurare un cluster esteso per un dominio di gestione VCF.  Questa procedura include la distribuzione di host vSphere e vCenter Server, l'installazione di strumenti ONTAP , la protezione dei datastore con SnapMirror Active Sync, la migrazione delle VM verso datastore protetti e la configurazione di storage supplementare.

image:vmw-vcf-vmsc-mgmt-smas-001.png["Stretch Cluster con ONTAP per il dominio di gestione VCF"]

Per SAN sono supportate sia configurazioni di cluster estesi uniformi che non uniformi. Nel caso di NAS, si tratta di una configurazione attivo-passivo con ONTAP 9.19.1.

[NOTE]
====
Le impostazioni di prossimità dell'host vengono utilizzate con la configurazione multipath per garantire la selezione del percorso ottimale per il traffico storage. Le impostazioni di prossimità dell'host vengono configurate su igroup nel caso di SCSI e su subsystem nel caso di NVMe-oF. Ad esempio, nella configurazione Uniform host access, l'host ha accesso a entrambi i sistemi storage nel cluster esteso. Nella configurazione multipath, i percorsi ottimali e non ottimali vengono configurati in base alle impostazioni di prossimità dell'host.

====


[[scenario-overview]]
== Panoramica dello scenario

La soluzione di cluster esteso può essere implementata sul cluster predefinito o su un cluster aggiuntivo nei domini di gestione o di workload VCF. ONTAP tools 10.6 supporta la protezione del datastore con SnapMirror active sync per i datastore VMFS sui protocolli iSCSI e FC. ONTAP supporta SnapMirror active sync per SAN (con iSCSI, FC, NVMe-oF) e NAS (NFS v3 e NFSv4.1). Per i protocolli SAN la protezione viene eseguita a livello di consistency group, mentre per NAS viene eseguita a livello di SVM. Il diagramma seguente illustra la soluzione di cluster esteso per un dominio di gestione VCF con ONTAP tools per VMFS con FC.

image:vmware-vcf-asa-mgmt-stretchcluster-002.png["Stretch Cluster con ONTAP per il dominio di gestione VCF"]

.Archiviazione principale sul dominio di gestione
[%collapsible%open]
====
. Distribuisci il dominio di gestione VCF con qualsiasi protocollo supportato.
+
.. Per VMFS su FC e NFSv3, viene utilizzato direttamente lo strumento VCF Installer. Nel caso di iSCSI, NVMe-oF e NFSv4.1, devi configurarlo con vCenter e poi usare lo strumento VCF Installer per distribuire il dominio di gestione. Per ulteriori informazioni, consulta link:vmw-vcf-migrate.html["Implementazione del dominio di gestione VCF con iSCSI, NVMe-oF e NFSv4.1"]


. Distribuisci gli ONTAP tools for VMware vSphere
. Distribuisci il plug-in SnapCenter per VMware vSphere (facoltativo)
. Proteggi il datastore.
+
.. Per iSCSI e FC, ONTAP tools 10.6 o versioni successive si usano per proteggere i datastore. Nel caso di NVMe-oF e NFSv4.1, utilizza system manager per proteggere i datastore. Per riferimento, guarda la demo video qui sotto per NVMe/TCP e NFS.




====
.Archiviazione supplementare sul dominio di gestione
[%collapsible%open]
====
Una volta che il dominio di gestione è attivo e funzionante, puoi creare ulteriori datastore utilizzando ONTAP tools 10.6 o versioni successive e proteggerli con SnapMirror active sync per iSCSI e FC. Per NVMe-oF e NFS, guarda la demo video qui sotto come riferimento, dato che la demo viene eseguita su un workload domain, ma puoi seguire gli stessi passaggi anche per il dominio di gestione.

====
